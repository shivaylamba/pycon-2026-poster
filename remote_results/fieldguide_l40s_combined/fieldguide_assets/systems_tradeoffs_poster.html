Overview

Generative AI is everywhere, but the cost and energy impact of everyday LLM calls is usually hidden in dashboards, invoices, and GPU logs. This poster turns those numbers into a reproducible Python field guide for choosing local models and hardware.

We profile code generation, document summarization, chat completion, semantic/RAG search, and batch embeddings across model sizes, quantization levels, architectures, and CPU/GPU configurations.

Thesis: the most accurate LLM is often not the most economically efficient one. LLM deployment is a systems engineering problem, not just a model selection problem.

What Happens During One LLM Request?

Each request moves through CPU preparation, serving overhead, GPU inference, KV-cache growth, sampling, and response parsing. The benchmark records row-level traces instead of one opaque latency number.

Quantization Efficiency

Precision is a deployment lever: it changes VRAM pressure, memory traffic, latency, and energy before application code changes.

Practical Heuristics
Benchmark workloads, not model cards.Chat, code, RAG, and embeddings stress different bottlenecks.
Quantization is infrastructure.It reduces memory movement and often improves tokens per joule.
GPUs win with concurrency.Small one-off calls hide GPU benefits; batches reveal them.
Keep two energy views.Raw energy for facility cost, net active energy for model comparison.
